# Royal Hotel — QA handoff 2026-09-23

## Automated result

- `php artisan test --compact`: 21 passed, 80 assertions.
- `npm run build`: passed.
- `php artisan view:cache`: passed.
- `composer audit --no-interaction`: no known advisories.
- `npm audit --audit-level=low`: 0 vulnerabilities.

## Browser checks performed

- Customer: frosted header transition, single logout action, account menu, room album, responsive
  room-detail layout, inline date/availability refresh, room selection, booking handoff and Back.
- Customer login: the remember-login checkbox is selected by default; its requested login flow sets
  Laravel's signed, HttpOnly remember cookie.
- Staff: room matrix at narrow width, search/filter layout, right-edge room drawer, hold dialog,
  refund workspace, confirmation dialog, profile light/dark appearance and internal login alignment.
- Admin: dashboard metrics layout, sidebar continuity, user search empty state, create-user editor,
  pricing editors, refund entry and dark/light theme contrast.
- Popup sizing was checked against the viewport; dangerous operations use the shared confirmation
  dialog rather than a browser-native confirm box.

## Behavior verified in code and tests

- Customer and internal route contexts remain role separated.
- Room holds expire after 30 minutes unless confirmed or paid.
- Check-in, checkout, cancellation and refund state changes cannot be repeated incorrectly.
- Late checkout charges 50% of one nightly room rate, independent of the stay total.
- Room status cannot be changed from occupied to cleaning to bypass checkout settlement.
- Customer payment pages require ownership and an eligible booking state.

## Environment limits

No real booking, refund, email or payment-provider transaction was submitted during browser QA.
Provider callbacks, SMTP delivery, Google Maps and a Strix agent scan need external credentials or
Docker Engine and therefore remain integration checks for the deployment environment.
